# Scale eval — where does vectorless retrieval bend?

Measure how retrieval quality and cost change as the wiki grows from ~19 to
~500 pages, using the real pipeline end-to-end. Runner: `scripts/eval-scale.sh`.
Oracle (no LLM): `scripts/verify-scale-eval.sh` (F1–F6).

checks:
  - check: "G1 scale-parity — every R/M check green at size 0 is green at size 480 (same questions, same graders, 25x the corpus)"
    false_pass: "filler avoids the needles' topics entirely, so nothing ever competes and navigation is trivially easy"
    mitigation: "filler is generated IN the needle domains' vocabulary (retention windows, retry ceilings, peak throughput) for other named services, with figures provably disjoint from every needle figure — oracle F3 greps both the blocklist (zero leaks) and the distractor terms (must be present)"
  - check: "G2 reads-budget — max wiki+raw file reads per answered question at size 480 <= 12"
    false_pass: "the agent greps the whole tree into context instead of Reading files, so the Read count stays low while context cost explodes"
    mitigation: "query-trace.py counts Grep/Glob tool calls AND Bash commands shelling out to grep, reported per question next to reads; a low-reads/high-greps row is visible in the report, and the reads column only earns the gate on questions that also passed their correctness check"
  - check: "G3 index-integrity — at size 480 the needle pages are index-linked AND the filler index-entry count still equals the manifest count after real ingest"
    false_pass: "ingest truncates or rewrites the index down to the needles, making navigation easy by destroying the corpus the eval is about"
    mitigation: "the gate counts surviving filler entries against .scale-manifest, so shrinking the index fails G3 even while it would make G1/G2 easier"
  - check: "F1 filler-determinism — two generations at the same N produce identical content sha256 manifests"
    false_pass: "hash covers only filenames, so content drift (clock, randomness) goes unnoticed and runs stop being comparable"
    mitigation: "the manifest hashes every generated byte (sorted concatenation of all filler pages); oracle F1 generates twice and compares"
  - check: "F5 trace-fidelity — query-trace.py extracts the exact answer text and exact read/grep counts from a fixture stream transcript, and falls back to raw bytes on unparseable input"
    false_pass: "a lenient parser silently returns empty answers or zero counts, making every question INCONC-or-cheap"
    mitigation: "oracle F5 asserts exact counts on a hand-built fixture and asserts API-error markers survive the fallback path so retr_answer_broken still fires"

holdout: "tests/eval/retrieval-questions-holdout.md (H1 unseen modality + H4 anti-reflex) run at size 480 via eval-retrieval.sh --holdout --scale=480 only — never by the default eval-scale.sh run, never in CI. If the main curve is green and the holdout at scale is not, the curve is Goodhart, not capability."
